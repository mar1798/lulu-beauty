# План: бэкенд-приложение `apps/api` (Python + FastAPI + PostgreSQL) для Lulu Beauty

## Контекст

Проект `lulu-beauty` — это онлайн-«витрина» без оплаты: покупатели набирают товары в корзину и оформляют **заявку** (не заказ с платежом), а владелец магазина видит все заявки и выгружает их в Excel. Сейчас в монорепе есть фронтенд (`apps/website` на Next.js, библиотека UI `packages/widgets`) и стартовый скелет бэкенда `apps/api` на **Python + FastAPI** (после миграции с исходного прототипа на NestJS/Prisma — см. `## Done`).

Нужно спроектировать и (по итогам) реализовать **всё целиком**: бэкенд `apps/api`, общие типы для фронта, страницы витрины/корзины/админки на `apps/website` и недостающие компоненты в `widgets`.

**Ключевые решения (утверждены с пользователем):**
- **Авторизация:** телефон + пароль + имя. OTP-подтверждение доставляется через **Telegram-бот** (пользователь один раз нажимает Start и делится контактом, чтобы привязать номер к chat_id).
- **Владелец:** пока один, роль ADMIN, засевается из env. Модель ролей простая, но расширяемая.
- **Дедлайны — календарь:** владелец сам управляет календарём дат-дедлайнов (создаёт/меняет/удаляет). Каждая дата = цикл заказов. За сутки до дедлайна — напоминание в Telegram тем, у кого есть товары в корзине, но нет чекаута; в дедлайн незачекаученные корзины очищаются.
- **Товар:** только **флаг наличия** (`inStock: boolean`), без числовых остатков. Цена — только для отображения.
- **Каталог:** ручной CRUD в админке **и** массовый импорт из Excel/CSV.

## Технологический стек

| Область | Выбор | Обоснование |
|---|---|---|
| Фреймворк | **FastAPI** (Python 3.12, ASGI/uvicorn) | Асинхронный, типизированный на Pydantic, автогенерация OpenAPI из коробки. |
| Пакетный менеджер | **uv** | Быстрый, детерминированный (`uv.lock`), не npm-workspace — независим от Turborepo. |
| ORM | **SQLAlchemy 2.0 (async)** + `asyncpg` | Типобезопасные декларативные модели, зрелая экосистема, хороший контроль над сложными запросами/транзакциями. |
| Миграции | **Alembic** | Стандарт для SQLAlchemy; автогенерация ревизий из `Base.metadata`. |
| БД | **PostgreSQL 16** | Реляционные связи + нативные enum. |
| Аутентификация | **JWT** access + refresh (`python-jose`/`PyJWT`) | Stateless access, ротация refresh для долгих сессий. |
| Хеш пароля | **argon2** (`argon2-cffi`) | Рекомендация OWASP (bcrypt/`passlib` — допустимый fallback). |
| OTP | **Telegram-бот** через `aiogram` (или `python-telegram-bot`) | Бесплатно, без SMS-шлюза; асинхронный, ложится на FastAPI event loop. |
| Планировщик | **APScheduler** (или периодическая fastapi background task), свипы по БД | Крон перечитывает даты циклов из БД → устойчиво к рестартам (без in-memory таймеров). |
| Excel/CSV | **openpyxl** (импорт+экспорт xlsx) + стандартный `csv`/**pandas** для CSV | Одна экосистема для парсинга и стилизованного экспорта. |
| Файлы | **Локальный диск** за интерфейсом `StorageService` | Просто для MVP, легко заменить на S3. |
| Валидация | **Pydantic v2** схемы (`pydantic-settings` для конфига) | Встроено в FastAPI, единый источник валидации запросов/ответов. |
| Конфиг | **`pydantic-settings`** (`app/config.py`, `Settings`) | Fail-fast при отсутствии обязательных env. |
| Тесты | **pytest** + **pytest-asyncio** (`asyncio_mode = "auto"`), `httpx.AsyncClient` против приложения | Стандарт для async FastAPI-тестирования. |
| Линт/типы | **ruff** (lint) + **mypy** (`strict = true`) | Быстрый линтер + строгая статическая типизация. |
| API-докс | Встроенный **FastAPI OpenAPI/Swagger** (`/docs`) | Авто-OpenAPI для фронт-команды, без доп. библиотек. |

## Модель данных (SQLAlchemy)

**Enum:** `Role {CUSTOMER, ADMIN}`, `OrderStatus {PENDING, CONFIRMED, READY, COMPLETED, CANCELLED}`, `CycleStatus {UPCOMING, ACTIVE, CLOSED}`, `OtpPurpose {REGISTER, LOGIN}`.

- **User** — `id(uuid)`, `phone(unique, E.164)`, `name`, `password_hash`, `role(=CUSTOMER)`, `telegram_chat_id(bigint, null, unique)`, `phone_verified(bool)`, timestamps.
- **RefreshToken** — `user_id`, `token_hash`, `expires_at`, `revoked_at?` (ротация при refresh).
- **OtpCode** — `user_id`, `code_hash`, `purpose`, `expires_at`, `consumed_at?`, `attempts` (TTL ~5 мин, лимит попыток).
- **Category** — `id`, `name`, `slug(unique)`, `sort_order`.
- **Product** — `id`, `name`, `slug(unique)`, `description`, `price_cents(int, только отображение)`, `category_id?`, `in_stock(bool)`, `deleted_at?` (soft-delete, чтобы старые снапшоты заявок оставались валидны).
- **ProductImage** — `product_id`, `url`, `alt`, `sort_order`, `is_primary`.
- **Cart** — `id`, `user_id`, `cycle_id`, timestamps. **Unique(user_id, cycle_id)** — одна корзина на пользователя в цикле.
- **CartItem** — `cart_id`, `product_id`, `quantity(>=1)`, Unique(cart_id, product_id).
- **OrderCycle** — `id`, `deadline_at(timestamptz)`, `label`, `status`, `reminder_sent_at?`, `closed_at?`. Это управляемый владельцем **календарь дедлайнов**.
- **Order** — `id`, `user_id`, `cycle_id`, `status(=PENDING)`, `total_cents(снапшот)`, `note?`, timestamps.
- **OrderItem** — `order_id`, `product_id?`, **денормализованный снапшот**: `product_name`, `product_price_cents`, `quantity` (не зависит от последующего редактирования товара).

**Активный цикл:** `CyclesService.get_active_cycle()` = цикл с ближайшим будущим `deadline_at` (`deadline_at > now() ORDER BY deadline_at ASC LIMIT 1`). Одновременно активен ровно один цикл; планировщик двигает UPCOMING→ACTIVE→CLOSED.

**Связь корзины с циклом:** при первом добавлении товара `CartService` находит/создаёт корзину пользователя в текущем активном цикле. В дедлайн незачекаученные корзины этого цикла очищаются. `Order` всегда хранит `cycle_id` для отчётов/экспорта по циклам.

## Структура модулей

```
apps/api/app/
  main.py            # create_app(): FastAPI instance, роутеры, CORS, exception handlers
  config.py          # Settings (pydantic-settings), DATABASE_URL/PORT/JWT/OTP/Telegram/…
  db.py              # async engine/async_sessionmaker, Base, get_session dependency
  common/            # guards-эквиваленты (auth dependencies), decorators/utils, exception handlers
  health/            # GET /health — реальная проверка БД
  auth/              # роутер + сервисы (register/login/verify-otp/refresh/logout), JWT, OTP
  users/             # GET/PATCH /users/me
  catalog/           # категории/товары CRUD, публичное чтение, загрузка картинок, импорт
  cart/               # find-or-create по активному циклу, позиции
  orders/            # checkout, статусы, admin-вью
  cycles/            # CRUD календаря дедлайнов, get_active_cycle
  telegram/          # бот: /start + привязка контакта, sendOtp/sendReminder
  export/            # экспорт заявок в xlsx по циклу
  storage/           # интерфейс StorageService + локальный драйвер
migrations/          # Alembic env.py + versions/
tests/                # pytest + pytest-asyncio, httpx.AsyncClient
```

- **auth** — роутер (`register`, `login`→выдаёт OTP, `verify-otp`, `refresh`, `logout`); сервисы `AuthService`, `OtpService`, `TokenService`; JWT-зависимости (аналог guard'ов) для access/refresh, dependency для проверки роли ADMIN.
- **users** — `UsersService`, `GET/PATCH /users/me`.
- **catalog** — категории (CRUD + публичный список), товары (публичное чтение + admin CRUD + загрузка картинок), `POST /catalog/import` multipart → `ImportService` upsert с summary created/updated/errors. ADMIN-only на запись.
- **cart** (JWT) — `GET /cart`, add/update/remove item, empty; `CartService` (find-or-create по активному циклу).
- **orders** — покупатель: `POST /orders/checkout`, `GET /orders`, `GET /orders/{id}`; админ: `GET /admin/orders?cycle_id=`, `PATCH /admin/orders/{id}/status`. Checkout = транзакция: снапшот корзины → Order+OrderItems → очистка корзины.
- **cycles** — admin CRUD дат-дедлайнов (календарь), `GET /cycles/active`; `CyclesService`; `CycleSchedulerService`.
- **telegram** — `TelegramService` (жизненный цикл бота, `send_otp`, `send_reminder`, `/start` + привязка контакта); за интерфейсом `NotificationsService` для будущей смены канала.
- **export** — `GET /admin/export/orders?cycle_id=` (стрим xlsx через openpyxl).
- **storage** — интерфейс `StorageService` + `LocalDiskStorage` (пишет `./uploads`, отдаёт `GET /files/{key}`); S3 позже.

## Поток Telegram OTP

- **Привязка («нажать Start один раз»):** deep-link `t.me/<bot>?start=<nonce>` → хендлер `/start` просит поделиться контактом кнопкой `request_contact` → Telegram возвращает подтверждённый телефон + `chat.id` → сохраняем в `User` (если зарегистрирован) или в `PendingTelegramContact` по нормализованному телефону.
- **Регистрация:** `POST /auth/register {phone,name,password}` → создать User (argon2, `phone_verified=false`) → 6-значный OTP → `OtpCode{code_hash, REGISTER, +5мин}` → найти chat_id → `send_otp`. `POST /auth/verify-otp {phone,code,purpose}` → проверка (не истёк/не использован, attempts<max) → пометить verified, погасить OTP, привязать chat_id, выдать access+refresh JWT.
- **Логин:** `POST /auth/login {phone,password}` → проверка хеша → OTP(LOGIN) → `verify-otp` → токены.
- **Безопасность:** хранить только **хеш** кода; TTL 5 мин; max 5 попыток; лимит повторной отправки (1/30с); периодическая очистка истёкших кодов.

## Планировщик (устойчив к рестартам, из БД)

**APScheduler** (или периодические задачи через `asyncio` + FastAPI lifespan) — крон-**свипы по БД** (не per-cycle таймеры). `CycleSchedulerService`:
- **Свип напоминаний** (~каждые 5–60 мин): циклы с `deadline_at` в окне [now+24ч …] и `reminder_sent_at IS NULL` → уведомить пользователей с непустой корзиной без чекаута → выставить `reminder_sent_at` (идемпотентно).
- **Свип дедлайнов:** циклы с `deadline_at <= now()` и `status != CLOSED` → транзакция: очистить корзины цикла у пользователей без Order в нём; `status=CLOSED`, `closed_at`; активировать следующий UPCOMING.
- **Очистка OTP:** удалить истёкшие/использованные коды.

Идемпотентность через колонки (`reminder_sent_at`/`status`/`closed_at`) → безопасно при рестартах и пересечении тиков. Все времена в `timestamptz` (UTC); `CYCLE_TIMEZONE` для расчётов/отображения.

## Docker

- **`apps/api/Dockerfile`** — multi-stage на `python:3.12-slim`: builder (`uv sync --frozen --no-dev`, кэш `/root/.cache/uv`) → runtime (копия `/app` включая `.venv`, non-root `apiusr`, `EXPOSE 3001`). Entrypoint: `sh -c "alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-3001}"` (миграции на старте, идемпотентно). Контекст сборки — **`apps/api`** (не корень репо), т.к. это независимый Python-проект без npm-workspace зависимостей.
- **`docker-compose.yml`** (в корне) — `db` = `postgres:16-alpine` (named volume `pgdata` + healthcheck `pg_isready`, порт 5432 наружу); `api` = `build.context: apps/api`, `depends_on: db(service_healthy)`, `env_file: apps/api/.env`, `DATABASE_URL` всегда переопределён на хост `db` (не зависит от того, что в `.env`), порт 3001. `.dockerignore` исключает `.venv`, `__pycache__`, `.mypy_cache`, `.ruff_cache`, `.pytest_cache`, `.env`, `tests`.

## Env (`apps/api/.env.example`)

Уже заведено:
```
PORT=3001
DATABASE_URL=postgresql+asyncpg://lulu:lulu@localhost:5432/lulu
POSTGRES_USER=lulu  POSTGRES_PASSWORD=lulu  POSTGRES_DB=lulu

ENVIRONMENT=development  CORS_ORIGIN=http://localhost:3000
JWT_ACCESS_SECRET=  JWT_ACCESS_TTL_SECONDS=900  JWT_REFRESH_SECRET=  JWT_REFRESH_TTL_SECONDS=2592000
OTP_TTL_SECONDS=300  OTP_MAX_ATTEMPTS=5
TELEGRAM_BOT_TOKEN=  TELEGRAM_BOT_USERNAME=
OWNER_PHONE=  OWNER_NAME=  OWNER_PASSWORD=       # сид единственного владельца
CYCLE_TIMEZONE=Asia/Bishkek  CURRENCY=KGS
STORAGE_DRIVER=local  UPLOAD_DIR=./uploads  PUBLIC_FILES_BASE_URL=http://localhost:3001/files
```

Отличие от исходного плана: TTL берутся в секундах (`*_TTL_SECONDS`, int), а не в строках вида `15m`/`30d` — так проще валидировать через `pydantic-settings` без кастомного парсера длительностей, и это единообразно с уже принятым `OTP_TTL_SECONDS`.

`Settings` (`app/config.py`, `pydantic-settings`) — fail-fast при отсутствии обязательных полей. Сид владельца — скрипт (`app/scripts/seed.py` или Alembic data-migration), апсертит ADMIN-владельца из `OWNER_*` (argon2), запуск `uv run python -m app.scripts.seed`.

## Общие типы и интеграция с фронтом

- **В `packages/widgets/src/types.ts`** (JSON-сериализуемые, их рендерит сайт): `ICategory`, `IProduct` (`priceCents`, `inStock`, `images: IImage[]`), обёртки списков/пагинации, `ICartItem`/`ICart`, `IOrder`/`IOrderItem`, `IOrderCycle` (`deadlineAt` как ISO-строка), `IAuthUser`. Enum — **строковые union-типы** (не TS enum), чтобы оставаться JSON-сериализуемыми; на бэке — Python `Enum`/`StrEnum`, сериализуемые Pydantic в те же строковые значения (camelCase на границе API через `alias_generator`/`by_alias=True`, чтобы не тащить snake_case в JSON-контракт). Дописать в существующий `types.ts` можно без правки манифеста (subpath `widgets/types` уже есть); `exports`+`typesVersions` в `packages/widgets/package.json` править нужно **только** при добавлении нового subpath.
- **Только на бэке (`apps/api`):** Pydantic request/response-схемы, SQLAlchemy-модели, JWT-payload, auth-зависимости.
- **Website:** добавить `NEXT_PUBLIC_API_BASE_URL` в `apps/website/.env.example` (и в `publicConfig`); тонкий fetch-клиент в `apps/website/src/services/api.ts`, импортирующий типы из `widgets/types` (data-fetching держим в website, не в widgets — по CLAUDE.md). FastAPI CORS (`CORSMiddleware`) разрешает origin сайта.
- **Frontend-страницы:** каталог + карточка товара, корзина с таймером до дедлайна, флоу авторизации (телефон/пароль/OTP), админка (CRUD товаров, импорт, календарь дедлайнов, список заявок + кнопка экспорта в Excel). Недостающие визуальные компоненты (карточка товара, поля форм, таблица заявок, календарь) генерируются через `npm run generate -w widgets`.

## Конфигурация проекта / Turbo / package.json

- **`apps/api` не является npm-воркспейсом** — нет `package.json`, исключён из `apps/*` glob'а Turborepo. Управляется исключительно `uv`/Docker; `npm run check`/`npm test` его не затрагивают (см. Backend-specific команды в `CLAUDE.md`).
- **`apps/api/pyproject.toml`** — `uv`-проект (`hatchling` build-backend), зависимости и dev-группа (`pytest`, `pytest-asyncio`, `httpx`, `ruff`, `mypy`) уже заведены; `[tool.ruff]`/`[tool.mypy]` (`strict = true`) настроены.
- **`apps/api/alembic.ini` + `migrations/`** — `env.py` читает `DATABASE_URL` из `app.config.settings`, `target_metadata = Base.metadata`. Новые ревизии — `uv run alembic revision --autogenerate -m "..."`, коммитить `migrations/versions/*`; Docker-образ только применяет (`alembic upgrade head`), не генерирует.
- **`turbo.json`** — не трогаем ради `api` (не воркспейс); при необходимости координации (например, `docker compose up` из корневого dev-скрипта) — отдельный npm-скрипт в корневом `package.json`, вызывающий `docker compose`, а не turbo-задача.

## Проверка (end-to-end)

1. `docker compose up --build` → поднимается `db` (healthcheck) и `api`, `alembic upgrade head` применяется на старте, сид создаёт владельца.

- **Авторизация только через Telegram: пароля и кодов больше нет.**
  - **Почему снесли пароль.** Восстановление шло тем же каналом, что и вход (`forgot-password` → OTP в бот), поэтому пароль защищал ровно от того, от кого не защищал: кто владеет Telegram — сбросит пароль. Стоил он при этом двух страниц восстановления, колонки `password_hash`, `OtpPurpose.RESET_PASSWORD` и зависимости `argon2-cffi`. Кнопка «Поделиться номером телефона» даёт больше: номер подтверждает **сам Telegram** (`contact.user_id == from_user.id`, проверка была и раньше).
  - **Вход — сессия, которую подтверждает бот.** `POST /auth/telegram/session` заводит `TelegramAuthSession` и отдаёт ссылку `t.me/<bot>?start=<payload>`; `/start` с этим payload'ом привязывается к чату (`attach_chat`), а дальше либо чат уже привязан к аккаунту — и вход подтверждается сразу, либо бот просит контакт, и подтверждение случается на нём. Вкладка всё это время опрашивает `POST /auth/telegram/claim`.
  - **Два секрета, а не один.** `link_payload` уезжает в ссылку и оседает видимым текстом в переписке; `poll_secret` остаётся в браузере (httpOnly-cookie на стороне Next) и хранится хешем. Опрос по payload'у означал бы, что подтверждённый вход забирает любой, кто эту переписку увидел, — расшаренный экран или пересланное сообщение.
  - **Состояния — таймстемпами** (`authorized_at`, `consumed_at`, `expires_at`), без отдельного enum: так «подтверждена и не потрачена» не может разойтись со статусом. Сессия одноразовая — ссылка входа стоит ровно один вход, дальше живут куки. TTL — 5 минут (`AUTH_SESSION_TTL_SECONDS`), протухшие и потраченные подметает планировщик (бывшая уборка OTP).

Обе сущности удалены вместе с `otp_codes` в миграции `9e7fa9bbcec2`.
