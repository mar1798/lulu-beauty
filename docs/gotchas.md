# Gotchas

Traps this repo is known to contain. Each is something that fails in a way that doesn't point
at its cause.

## Repository-wide

**`apps/api` is invisible to npm.** It has no `package.json`, isn't a workspace, and
`npm run check` / `npm test` do not touch it. Run `ruff`, `mypy` and `pytest` separately.

**npm only.** `packageManager: npm@10.9.0`, committed `package-lock.json`, CI runs `npm ci`.
pnpm or yarn will produce a lockfile nothing else uses.

## `apps/website`

**`src/сonfig.ts` is spelled with a Cyrillic `с` (U+0441)**, and so is the import specifier
`@/сonfig`. Typing an ASCII `c` gives an unresolved module that looks like a path mistake.
Copy the path from an existing import.

**`dev` and `build` must keep `--webpack`.** Next 16 defaults to Turbopack, but the
vanilla-extract plugin wired in here is the webpack one.

**The dev server reloads itself every ~90 seconds when opened from a phone or Telegram.** Not
a crash: Next 16 blocks `/_next/*` (including the HMR websocket) for any origin but
`localhost`, the HMR client retries 25 times and then calls `location.reload()`. Private
network ranges are already allowed in `next.config.js`; a tunnel hostname goes in
`NEXT_DEV_ORIGINS`.

**A new third-party script, iframe or API host needs a CSP edit** in `next.config.js`, or it
silently fails in the browser. `X-Frame-Options` is deliberately absent — it cannot express
"allow Telegram only", which `frame-ancestors` does, and the site runs as a Mini App inside
`web.telegram.org`.

**SWR `fallback` keys must go through `unstable_serialize`.** `useSWR` accepts tuples, but
`fallback` looks up the serialized form; a raw tuple never matches, with no error.

**`fallback` and `fallbackData` are revalidated on mount by default**, so prefilling a key
from `getStaticProps` does not, by itself, remove the request — it just moves it into the
hydration second. Pair the prefill with `revalidateOnMount: false` (`hasFallback` in
`services/swrFallback.ts`).

**Don't hand `onIdle` a `timeout` unless the work really has a deadline.** A bare
`requestIdleCallback` waits for genuine idle; a timeout forces the work through while the page
is still settling. Giving `usePrefetchRoutes` a 2 s deadline cost `/catalog` 1.8 s of LCP in
Lighthouse — prefetching three routes right as the first screen was finishing.

**Query-parameter casing is inconsistent by accident.** Public `GET /products` takes
`in_stock` / `page_size`; admin `GET /admin/products` takes `inStock` / `pageSize` /
`includeDeleted`. Check the router.

**A new backend error code without an entry in `src/services/apiErrors.ts`** shows the user a
status-based placeholder instead of an explanation.

**Admin chunks are publicly fetchable.** The `/admin/*` gate is a client-side redirect for UX;
authorization is on the API. Never put a secret in the admin UI.

**`getServerSideProps` exists nowhere in the app**, deliberately. Adding one changes what
`next build` produces and what the deployment has to run.

## `packages/widgets`

**Never import `next/*`.** Storybook has no Next runtime; adapters come through
`ServicesContext`.

**Don't hand-edit barrel `index.ts` files.** They're generated by `barrelsby` from
`.barrelsby.json`; run `npm run barrels`.

**`themes/tokens.ts` must import `../lib/rem` and `../lib/shadow` directly, never the `lib`
barrel.** The barrel pulls `lib/color.ts`, which imports `contract.css.ts`, closing an
initialization cycle: `color` initializes before `vars` is ready.

**Theme colors are `'R, G, B'` channel strings**, because `color()` composes `rgb()`/`rgba()`
from them. A hex value there produces invalid CSS silently.

**A new public subpath needs entries in both `exports` and `typesVersions`** in
`package.json`. One without the other resolves at runtime but not for types, or vice versa.

**Use `renderWidget`, not bare `render`, in tests** — otherwise anything touching
`AppLink`/`AppImage` fails on an empty `ServicesContext`.

**No Tailwind, no Radix, no shadcn runtime.** Reference implementations are hand-ported into
vanilla-extract. Never run `shadcn add` here.

## `apps/api`

**A new model not imported in `app/models.py` is silently missing from autogenerated
migrations.** The migration applies cleanly; the table just never appears.

**`Settings` is instantiated at import time**, and several fields have no default. Anything
importing `app.*` without them fails immediately — including Alembic. That's why
`tests/conftest.py` and the CI workflow seed placeholders.

**`uv run pytest` can silently skip every DB test.** The `tests/integration/` suite skips
itself when Postgres isn't reachable, so a green local run proves less than it looks.

**`uv run pytest` can also wipe your dev database.** `conftest.py` only `setdefault`s
`DATABASE_URL`, so `apps/api/.env` wins, and the fixture `TRUNCATE`s every table per test. Use
a dedicated `lulu_test` database — [testing.md](testing.md).

**Services must not commit.** The caller owns the transaction; notifications go out *after*
the commit, or a rolled-back state gets announced and cannot be retracted.

**More than one uvicorn worker multiplies the rate limit.** The token bucket is per-process
state, so each caller gets each worker's budget.

**`RATE_LIMIT_TRUST_FORWARDED_FOR=true` is only safe behind the website's proxy.** Expose the
API directly with it on and the header hands every caller unlimited identities.

**Long polling makes `uvicorn --reload` awkward while working on the bot** — this is why the
webhook mode exists, and why webhook registration failure falls back to polling rather than
raising (a bad bot setting must not take `/health` down).

**Telegram's Mini App signature excludes both `hash` and `signature`** from the hashed string.
Leaving `signature` in makes every Mini App login fail.

## Docker and data

**`docker compose down -v` orphans product images.** They live in the named `uploads` volume
while `product_images` rows live in the database; dropping one leaves the other dangling.

**Nothing in `npm run dev:*` passes `--build`.** After changing `apps/api/Dockerfile` or its
dependencies, run `docker compose up --build api` yourself.

**`Ctrl+C` after `npm run dev:all` stops only the frontend.** The api was started with `-d`;
stop it with `npm run dev:api:stop`.

**`NEXT_PUBLIC_*` is baked in at build time.** Changing one in production needs an image
rebuild, not a restart.
